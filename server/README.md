# Ретрансляция через сервер

OBS на ПК шлёт один поток на сервер, сервер без перекодирования раздаёт его на YouTube и Twitch. Для нескольких стримеров есть веб-панель: каждый сам вводит свои ключи и получает свой адрес для OBS.

StreamKit (озвучка чата) остаётся на ПК каждого стримера: ему нужны OBS, игра и звуковая карта. Звук попадает в эфир через OBS, как раньше.

```
ПК: StreamKit -> звук -> OBS --RTMP--> сервер (Docker) --> YouTube
                                                       \-> Twitch
```

## Что на сервере

Два контейнера в своих сетях, ничего общего с остальными сервисами сервера (VPN, nginx на хосте и т. д.):

| Контейнер | Что делает | Ограничения |
|---|---|---|
| `streamkit-edge` | nginx-rtmp на порту 1935, HTTPS панели на 8444, применяет настройки | только нужные capabilities |
| `streamkit-panel` | веб-панель (Flask) | без прав, диск только для чтения, нет интернета, нет портов наружу |

Единственное, что касается хоста: certbot хоста выпускает и продлевает сертификат, контейнеру отдаётся его копия (`/opt/streamkit/certs`), приватные ключи остального сервера в контейнеры не попадают.

## Установка (Ubuntu/Debian с Docker)

Нужны `docker`, `certbot`, имя сервера, которое указывает на его IP (если домена нет, подойдёт `<ip-через-дефисы>.sslip.io`), и работающий порт 80.

С ПК скопируй папку `server` и запусти:

```bash
scp -r server root@IP:~/streamkit-server
ssh root@IP
cd ~/streamkit-server
LE_AGREE_TOS=yes bash install.sh stream.example.com 203.0.113.10 admin
```

`LE_AGREE_TOS=yes` означает согласие с [условиями Let's Encrypt](https://letsencrypt.org/documents/LE-SA-v1.5-February-24-2025.pdf). Если раньше на хост ставился nginx-rtmp старой версией, добавь `MIGRATE_HOST_RTMP=yes`: его настройки сохранятся в `/root/nginx-rtmp-old`, а порт 1935 освободится.

В конце скрипт напечатает ссылку-приглашение для администратора.

## Как пользоваться

1. Администратор создаёт ссылку для человека: в панели (раздел «Администрирование») или командой

   ```bash
   docker exec -u 10001 streamkit-panel python3 /opt/streamkit-panel/cli.py invite liza
   ```

   Ссылка одноразовая, действует 24 часа. Повторное приглашение того же логина сбрасывает пароль и 2FA, ключи остаются.
2. Человек по ссылке придумывает пароль и добавляет приложение-аутентификатор.
3. В кабинете вписывает ключи YouTube и Twitch и берёт адрес для OBS.

## OBS / PRISM

Настройки → Вещание → Сервис «Пользовательский»:
- Сервер: адрес из кабинета, вида `rtmp://IP/u_<токен>`
- Ключ потока: `stream` (любое слово)

Настройки → Вывод (расширенный режим, «Потоковое вещание»):
- Управление битрейтом CBR, 6000 Кбит/с, интервал ключевых кадров 2 с
- Кодировщик NVENC или x264, профиль high, B-кадры 2 или меньше
- Звук AAC, 160 Кбит/с, 48 кГц

Один и тот же поток уходит на обе площадки, поэтому параметры должны подходить обеим.

## StreamKit

На вкладке «Основное» каждый стример указывает свой канал Twitch и свою трансляцию YouTube (ID или ссылка) и API-ключ.

API-ключ YouTube: [Google Cloud Console](https://console.cloud.google.com/) → проект → включить YouTube Data API v3 → Учётные данные → API-ключ (лучше ограничить только этим API). Квота бесплатно 10 000 единиц в день: StreamKit опрашивает чат не чаще раза в 8 секунд, это примерно 5–6 часов эфира на ключ. Каждому стримеру лучше завести свой ключ.

## Безопасность

- Регистрации нет, вход только по приглашению; пароль от 12 символов (scrypt) и код 2FA.
- 5 неверных попыток блокируют аккаунт на 15 минут; на вход и приглашения действует лимит запросов.
- Защита форм от подделки (CSRF), cookie `Secure`/`HttpOnly`/`SameSite=Strict`, строгие заголовки (CSP, HSTS).
- Ключи в браузере целиком не показываются. Они хранятся на сервере открытым текстом, потому что nginx должен передать их YouTube и Twitch; доступ к ним есть у администратора сервера.
- Ключи проверяются по строгому шаблону, поэтому вписать лишнюю команду в конфиг nginx нельзя; при ошибке `nginx -t` прежний конфиг возвращается.
- RTMP от OBS до сервера идёт без шифрования (особенность протокола). Секретный адрес `u_<токен>` защищает от подбора, но не от перехвата в сети.
- Все входы и действия пишутся в журнал (виден в админке, хранится 90 дней).

## Проверка и отладка

```bash
docker logs -f streamkit-edge      # nginx, публикации и push на YouTube/Twitch
docker logs -f streamkit-panel     # веб-панель
docker ps --filter name=streamkit
```

Тесты панели (на ПК, нужен Flask):

```bash
cd server/panel
COOKIE_SECURE=0 PANEL_DATA=<пустая папка> python -m unittest test_panel
```

## Удаление

```bash
docker rm -f streamkit-edge streamkit-panel
docker network rm streamkit-internal streamkit-public
docker volume rm streamkit-data streamkit-rtmpd   # удалит пользователей и ключи
rm -rf /opt/streamkit /etc/letsencrypt/renewal-hooks/deploy/streamkit.sh
```
